# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Проект: «Защитник снов»
### Жанр: атмосферный action-adventure / roguelite / narrative. Платформа: браузер (ПК), пиксель-арт 2D

Версия документа: 1.0
Статус: черновик для старта разработки (pre-production)

---

## 1. Общие сведения о проекте

### 1.1 Название
«Защитник снов» (рабочее английское название для сборок/репозитория: *Dream Keeper*).

### 1.2 Краткое описание
Атмосферная 2D-игра с видом сверху под углом, в которой игрок управляет душой Неро, застрявшей в мире забытых снов — Изнанке. Ключевая механика: ограниченная видимость вокруг персонажа и «туман забывания», который возвращается на исследованные territории, если их не закрепить ограниченным ресурсом («Якоря памяти»). Сюжет построен слоями обмана, каждый из которых меняет понимание игроком уже пройденной истории.

### 1.3 Цель документа
Зафиксировать функциональные, технические, художественные и организационные требования к первой играбельной версии (вертикальный срез / vertical slice), достаточные для начала производства и оценки трудозатрат.

### 1.4 Целевая аудитория
Игроки 16+, знакомые с жанрами atmospheric adventure / metroidvania-lite / roguelite (референсы: Hollow Knight, Hades, INSIDE, Little Nightmares), предпочитающие браузерные игры на ПК без установки клиента.

### 1.5 Референсы
- **Геймплей и структура мира:** Hollow Knight, Dead Cells.
- **Атмосфера и визуальный тон:** Little Nightmares, INSIDE.
- **Боевая система и темп:** Hades.
- **Механика видимости/тумана:** уникальная разработка проекта (нет прямого референса — ключевая отличительная фича).

---

## 2. Цели и задачи разработки

1. Реализовать уникальную механику «туман забывания + якоря памяти» как ядро игрового процесса, а не декоративный эффект.
2. Реализовать нелинейное восприятие сюжета через систему «слоёв твистов» (см. раздел 6) без необходимости менять уже написанный код уровней при добавлении новых слоёв повествования.
3. Обеспечить стабильную работу в браузере на ПК с целевым FPS ≥ 60 на средних конфигурациях.
4. Создать вертикальный срез (1 полноценная локация + 1 босс + основные механики) как основу для дальнейшего расширения на весь список локаций.

## 3. Платформа и технические требования

### 3.1 Целевая платформа
- Браузер на ПК: Chrome, Firefox, Edge (последние 2 major-версии на момент релиза каждой сборки).
- Экспорт в WebGL (WASM), без обязательной установки.
- Управление: клавиатура + мышь (обязательно), опциональная поддержка геймпада (Unity Input System / старый Input Manager).

### 3.2 Движок и стек
- **Движок:** Unity (Unity 6 LTS), язык — C#.
- **Платформа сборки:** WebGL (WASM), Unity WebGL Build Support.
- **Ключевые пакеты:** 2D (Tilemap, 2D Sprite), Input System, Universal Render Pipeline (URP) для 2D-шейдеров тумана/дизеринга, при необходимости — Unity Localization для таблиц текста.
- Выбор и настройка стека фиксируются на этапе прототипа (см. раздел 9) после теста производительности тумана.

### 3.3 Требования к производительности
- Целевой FPS: 60 на средней конфигурации (интегрированная графика уровня Intel Iris Xe, 8 ГБ RAM).
- Минимально допустимый FPS: 30 на слабых конфигурациях, с автоматическим снижением качества эффекта тумана (fallback-режим без дизеринга, упрощённый шейдер).
- Время первой загрузки страницы (до интерактивности): не более 8 секунд на соединении 10 Мбит/с.
- Объём начального билда (до подгрузки уровней): не более 25 МБ.

### 3.4 Разрешение и рендер
- Внутриигровое разрешение рендера: 384×216 px (кратно 16:9).
- Масштабирование до размера окна браузера: целочисленное, nearest-neighbor (без сглаживания пиксельной сетки).
- Полноэкранный режим: поддержка `Screen.fullScreen` (Fullscreen API под капотом Unity WebGL) как опция.

### 3.5 Сохранения
- Автосохранение через файл в `Application.persistentDataPath` (в WebGL это IndexedDB через Emscripten FS, приоритет) с fallback на `PlayerPrefs` (localStorage).
- Точки сохранения: при входе в новую зону, каждые 60 секунд в безопасных зонах, вручную из меню паузы.
- Формат сохранения: JSON с версионированием схемы (для совместимости при патчах).

### 3.6 Локализация
- На старте: русский язык (полная озвучка текста в UI, диалоги — текст, без обязательной войс-овер озвучки на первом этапе).
- Архитектура текста — вынесена в отдельные локализационные таблицы (CSV/JSON или пакет Unity Localization) с самого начала, даже если английский перевод не входит в объём первого релиза, чтобы не переписывать систему текста позже.

## 4. Функциональные требования по модулям

### 4.1 Модуль «Туман и видимость» (ядро проекта — наивысший приоритет)
| № | Требование |
|---|---|
| 4.1.1 | Вокруг персонажа существует «Поле Осознания» — радиус видимости (базовое значение конфигурируется, референс: 8 условных единиц). |
| 4.1.2 | Область за пределами радиуса не рендерится напрямую — рендерится плейсхолдер «туман» с анимированным дизерингом. |
| 4.1.3 | При приближении персонажа к границе тумана происходит плавное рассеивание (не мгновенное появление). |
| 4.1.4 | Открытая область остаётся видимой в течение таймера забывания (базовое значение: 30 секунд, конфигурируется по зонам). |
| 4.1.5 | По истечении таймера область постепенно снова затягивается туманом с анимацией, обратной п. 4.1.3. |
| 4.1.6 | Игрок может разместить «Якорь памяти» — объект, фиксирующий фиксированную область карты в открытом состоянии на неограниченное время (до уничтожения якоря врагом или сюжетным событием). |
| 4.1.7 | Количество одновременно активных якорей ограничено ресурсом, который наращивается по ходу игры (стартовое значение: 1, максимум в вертикальном срезе: 3). |
| 4.1.8 | Видимость карты хранится персистентно на уровне сессии — при выходе из зоны и возвращении открытые якорями области остаются открытыми, забытые — снова затуманены. |
| 4.1.9 | Технически: карта видимости реализуется через render texture / shader mask над пре-рендеренной статичной картой уровня, без пересчёта полигонов видимости на каждый кадр. |

### 4.2 Модуль «Передвижение и камера»
| № | Требование |
|---|---|
| 4.2.1 | Вид сверху под углом (изометрия/2.5D-имитация спрайтами) либо прямой топ-down — фиксируется на этапе арт-прототипа. |
| 4.2.2 | Управление: WASD/стрелки — движение, привязка камеры к персонажу с мягким запаздыванием (camera lag). |
| 4.2.3 | Коллизии со статичной геометрией уровня (стены, препятствия) через Unity Tilemap + `TilemapCollider2D`. |

### 4.3 Модуль «Боевая система»
| № | Требование |
|---|---|
| 4.3.1 | Базовый набор действий: атака (ЛКМ), способность (ПКМ/клавиша), уклонение (пробел), ультимейт (отдельная клавиша, требует накопления ресурса). |
| 4.3.2 | Базовая атака — «клинок души», ближний бой с коротким кадром анимации, без хитстопа дольше 100–150 мс (чтобы не ломать темп на слабом железе). |
| 4.3.3 | Система здоровья/урона с i-frames после получения удара (стандарт для action-adventure, референс — Hollow Knight). |
| 4.3.4 | Способности проектируются как модульные компоненты (см. 4.4), боевая система не хардкодит конкретные способности. |

### 4.4 Модуль «Способности» (расширяемый список)
Стартовый набор для вертикального срез:
- **Воспоминание** — временно (несколько секунд) раскрывает карту полностью, игнорируя радиус видимости.
- **Эхо** — показывает следы недавно прошедших врагов (визуальный след на карте на ограниченное время).
- **Сон** — кратковременная остановка времени для врагов в радиусе действия.
- **Забыть** — удаляет одного врага из игровой сцены безвозвратно (с ограничением по кулдауну/ресурсу).

Каждая способность реализуется как отдельный класс/скрипт с единым интерфейсом (стоимость ресурса, кулдаун, зона действия, визуальный и звуковой эффект), чтобы новые способности добавлялись без правки ядра боевой системы.

### 4.5 Модуль «Воспоминания» (нарративно-игровые модификаторы)
| № | Требование |
|---|---|
| 4.5.1 | По уровню размещены собираемые объекты «Воспоминания» с уникальным ID. |
| 4.5.2 | Каждое найденное Воспоминание триггерит: (а) запись в журнал лора, (б) конкретное изменение окружения в привязанной зоне уровня (визуальный эффект + возможное изменение геймплейных параметров — видимость, проходимость, состояние врагов). |
| 4.5.3 | Изменения окружения от Воспоминаний персистентны в рамках сохранения — не сбрасываются при повторном визите в зону. |
| 4.5.4 | Система поддерживает «взаимоисключающие» пары воспоминаний (нашёл одно — второе в этой зоне становится недоступно/неактуально) — конфигурируется в данных уровня, не в коде. |

### 4.6 Модуль «Враги и ИИ»
Фракции для вертикального срез (минимум): Шорохи (базовый враг, засада из тумана), Пожиратели (уничтожают исследованные зоны, приоритетная цель для игрока), один Искажённый (уникальный именной враг с диалоговыми репликами в бою).
| № | Требование |
|---|---|
| 4.6.1 | Базовый ИИ на конечном автомате (patrol → alert → attack → retreat) с параметрами, настраиваемыми в данных, а не в коде, для каждого типа врага. |
| 4.6.2 | Пожиратель при активации начинает «пожирать» открытую область карты (визуально и в системе видимости из 4.1) — если не уничтожен за N секунд, соответствующая область помечается как утраченная навсегда (отдельный статус, отличный от «забыто временно»). |
| 4.6.3 | Искажённые враги имеют закреплённые диалоговые реплики, воспроизводимые в момент вступления в бой и при получении критического урона (текст выводится через систему локализации, п. 3.6). |

### 4.7 Модуль «Боссы»
| № | Требование |
|---|---|
| 4.7.1 | Минимум 1 полноценный босс в вертикальном срезе (рекомендация — «Учитель», страх ошибки, как наименее технически сложный для прототипа). |
| 4.7.2 | Босс «Безликий» (если войдёт в срез) требует реализации позиционного звука (см. 4.9) как основного канала ориентации игрока — приоритет по сложности, закладывать отдельным этапом. |
| 4.7.3 | У каждого босса — минимум 2 фазы поведения, переключение по порогу здоровья. |

### 4.8 Модуль «Диалоги и нарратив»
| № | Требование |
|---|---|
| 4.8.1 | Диалоговая система на данных (JSON/Dialogue-таблицы), не хардкод в коде сцен. |
| 4.8.2 | Поддержка веток и условий показа реплики (флаг «найдено воспоминание X», «убит враг Y» и т.п.) — необходимо для слоёной подачи сюжета (см. раздел 6 GDD). |
| 4.8.3 | Система флагов сюжетного прогресса персистентна в сохранении и влияет на доступные концовки. |

### 4.9 Модуль «Звук»
| № | Требование |
|---|---|
| 4.9.1 | Реализация через Unity Audio (`AudioSource`/`AudioListener`, AudioMixer) с поддержкой позиционного (панорамируемого по 2D-координатам) звука (`AudioSource.panStereo` / Spatial Blend). |
| 4.9.2 | Отдельный слой звуковых подсказок для боя с боссом «Безликий» — направление звука должно однозначно считываться игроком без визуального контакта. |
| 4.9.3 | Опция доступности: визуальный индикатор направления звука (для слабослышащих игроков или игры без звука). |

### 4.10 Модуль «UI/UX»
| № | Требование |
|---|---|
| 4.10.1 | HUD: здоровье, ресурс способностей, счётчик доступных якорей памяти, индикатор таймера забывания активной открытой зоны. |
| 4.10.2 | Меню паузы: сохранение/загрузка, настройки (звук, графика/fallback-режим тумана, управление), выход. |
| 4.10.3 | Журнал воспоминаний/лора — отдельный экран со списком найденных Воспоминаний и их текстовым описанием. |
| 4.10.4 | Весь UI — в пиксельном стиле, единый шрифт (растровый, читаемый на маленьких размерах при масштабировании браузера). |

## 5. Художественные требования

### 5.1 Стиль
Пиксель-арт, тёмная палитра с точечными яркими акцентами. Ориентир по детализации спрайтов — между Hollow Knight (силуэтная чёткость) и Hyper Light Drifter (насыщенность цвета в акцентных объектах).

### 5.2 Палитра по зонам (обязательное требование, не рекомендация)
- Обычный мир Изнанки — холодная палитра (серо-синие, приглушённые тона), 16–20 цветов на зону.
- Зоны Воспоминаний — тёплая палитра, визуально контрастная с обычным миром.
- Зоны Кошмаров — почти монохромная палитра (2–4 базовых тона + 1 акцентный цвет).
- Приближение к Забвению — прогрессивное обесцвечивание шейдером (desaturation shader), привязанное к прогрессу уровня/сюжетному флагу.

### 5.3 Спрайты и анимация
- Размер тайла: 16×16 px (базовая единица сетки уровня).
- Персонаж (Неро): не менее 8 направлений либо 4 направления + отражение по горизонтали (решается на этапе прототипа исходя из вида камеры).
- Базовый набор анимаций персонажа: idle, walk, attack, ability x4, dodge, hit, death — минимум для вертикального срез.
- Туман: отдельный анимированный тайлсет с дизерингом, минимум 4 кадра анимации для избежания статичности.

### 5.4 Референс-борды
Перед началом продакшена — обязательный этап сбора референс-борда по каждой зоне вертикального срез (Moodboard), утверждённого до старта пиксель-арт продакшена, чтобы избежать переделок.

## 6. Нарративные требования (сюжетная архитектура)

Полная сюжетная структура и лор описаны в отдельном GDD-документе проекта (см. «Защитник снов — расширенный концепт»). Для ТЗ фиксируются только требования к **реализации**:

1. Сюжет подаётся слоями (минимум 5 сюжетных «слоёв твистов»), каждый активируется системой флагов (см. 4.8.3), не привязан жёстко к линейному прогрессу уровня — необходимо для поддержки NG+/повторного прохождения с иной интерпретацией уже пройденных зон.
2. Минимум 3 финальные развилки (концовки) должны быть реализуемы без дублирования уровней — через финальную сцену с вариативным диалогом и визуальным исходом, а не отдельные уровни на каждую концовку.
3. Скрытая («истинная») концовка требует отдельного условия — сбор всех Воспоминаний за прохождение; система должна отслеживать процент найденных Воспоминаний как отдельную переменную состояния.

## 7. Структура уровней (вертикальный срез)

Для первой играбельной версии (proof of concept):

1. **Пролог** — обучающая зона: механика тумана, базовое движение, первая атака.
2. **Лес** — первая полноценная зона с механикой якорей памяти, первый Пожиратель, первое собираемое Воспоминание, изменяющее окружение.
3. **Босс зоны «Лес»** — «Учитель» (страх ошибки).

Остальные зоны (Город-хаб, Заброшенный дом, Метро, Океан, Эхо, Чёрное море, Ядро сна) — во второй и последующих итерациях, после подтверждения ядра механик на вертикальном срезе.

---

## 8. Нефункциональные требования

- **Доступность:** визуальные подсказки для звукозависимых механик (п. 4.9.3), возможность отключить/упростить эффект дизеринга тумана для игроков с фотосенситивностью или слабым железом.
- **Стабильность:** отсутствие критических падений FPS (ниже 20) дольше 1 секунды при штатной игре на минимальной целевой конфигурации.
- **Кроссбраузерность:** идентичное поведение механики тумана и сохранений в Chrome, Firefox, Edge.
- **Расширяемость:** все игровые сущности (враги, способности, Воспоминания, диалоги) описываются данными (JSON/ресурсы движка), а не хардкодятся в логике сцен — обязательное архитектурное требование, так как список контента (боссы, зоны, воспоминания) будет расти после вертикального срез.

## 9. Этапы разработки

| Этап | Содержание | Ключевой критерий готовности |
|---|---|---|
| 0. Прототип механики | Реализация модуля тумана (4.1) на выбранном движке в виде «серого куба» — без арта, только механика | Туман рассеивается/забывается/фиксируется якорем корректно, 60 FPS на тесте |

## 10. Критерии приёмки вертикального срез

- [ ] Механика тумана работает согласно всем пунктам 4.1, без просадки ниже 60 FPS на средней конфигурации.
- [ ] Игрок может пройти Пролог → Лес → бой с боссом без критических багов и без потери прогресса при перезагрузке страницы (сохранение восстанавливается корректно).
- [ ] Минимум одно Воспоминание физически меняет геймплейную зону согласно 4.5.
- [ ] Минимум один Пожиратель безвозвратно уничтожает область карты, если не был остановлен игроком (4.6.2).
- [ ] Полный набор анимаций персонажа из 5.3 реализован и не содержит визуальных артефактов при масштабировании браузера.
- [ ] Автосохранение подтверждено рабочим в Chrome, Firefox и Edge.
